# Экспертная лаборатория

Сюжетная веб-игра по теории судебной экспертизы КР (лекции 2–3). Стажёр проходит смену из 4 глав и 17 дел, собирает улики и раскрывает главное дело. Есть рейтинг группы и кабинет руководителя.

**Стек:** Node.js 22 без зависимостей. Бэкенд — REST API (`server/`), база — SQLite: локально через `node:sqlite`, в облаке через [Turso](https://turso.tech) по HTTP. Фронтенд — ES-модули без сборки (`public/`). Хостинг на выбор: Netlify или Vercel (статика + одна serverless-функция) либо Render (один долгоживущий Node-процесс).

```

netlify/functions/api.mjs  вход для Netlify (Request/Response, см. netlify.toml)
render.yaml             настройки Render: `npm start` запускает server/local.js
server/
  app.js                маршруты и логика API (не зависит от платформы)
  auth.js               вход руководителя: пароль из ADMIN_PASSWORD, сессия в HttpOnly-cookie, защита от перебора и CSRF
  http.js               ответы, ошибки, cookie
  local.js              локальный сервер: статика + API
  db/                   index.js (выбор базы), sqlite.js, turso.js (HTTP-протокол v2/pipeline), schema.js
  game/                 rules.js (главы, баллы, звания), deck.js (выдача дел), story.js (улики, подозреваемые, концовки)
  data/cases.js         106 дел с правильными ответами — только на сервере
public/
  index.html, css/      base.css (токены, общие компоненты), game.css (сцены), admin.css
  js/main.js, router.js
  js/core/              api.js (клиент API), store.js (память устройства)
  js/ui/                dom.js (экранирующий шаблонизатор html``), characters.js (SVG-персонажи), components.js, fx.js (анимации)
  js/story.js           реплики персонажей
  js/views/             title, badge, game (сюжетный движок), rating, admin/{index,dashboard,ceremony}
tests/                  node:test — API на SQLite в памяти, адаптер Turso на поддельном сервере, адаптер Vercel
```

## Запуск локально

```bash
npm start            # http://localhost:3000, кабинет: /#/admin, пароль admin
npm test             # 9 тестов: API, Turso, адаптеры Vercel и Netlify, бюджет запросов, миграция
ADMIN_PASSWORD=секрет PORT=8080 npm start
```

Нужен Node.js 22.5 или новее: в нём есть встроенный `node:sqlite`. Ставить пакеты не нужно.

## Переменные окружения (Netlify / Render / Vercel)

| Переменная | Что это |
|---|---|
| `TURSO_DATABASE_URL` | адрес базы, `libsql://…turso.io` |
| `TURSO_AUTH_TOKEN` | токен доступа к базе |
| `ADMIN_PASSWORD` | пароль кабинета руководителя |

Таблицы создаются сами при первом запросе. Проверка настройки: `GET /api/health`.

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/config` | главы, лимит времени, описание главного дела |
| POST | `/api/attempts` | `{name, group, avatar}` → новая попытка (409 `BLOCKED`, если попытки кончились) или незаконченная |
| GET | `/api/attempts/:id` | состояние: фаза, прогресс глав, открытые улики, история ответов, итог |
| POST | `/api/attempts/:id/open` | открыть текущее дело — с этого момента сервер считает время |
| POST | `/api/attempts/:id/answer` | `{position, option}` → верно ли, правильный вариант, разбор, итог главы |
| POST | `/api/attempts/:id/deduction` | `{suspect}` → финал |
| GET | `/api/leaderboard?group=` | лучшая попытка каждого |
| POST | `/api/admin/login` · `logout` · `logout-all` | сессия руководителя |
| GET | `/api/admin/overview?group=` | игроки, попытки, статистика по темам и делам |
| POST | `/api/admin/players/:id/grant` · `/api/admin/grant-all` | дополнительные попытки |
| DELETE | `/api/admin/attempts/:id` | удалить попытку |
| GET | `/api/admin/export.csv` | выгрузка для Excel |

## Скорость

Каждое обращение к Turso — это отдельный сетевой запрос, поэтому сервер собирает запросы в пакеты (`db.batch`, один HTTP-запрос на пакет):

| Действие игрока | HTTP-запросов | Обращений к базе |
|---|---|---|
| Выйти на смену | 1 | 1 |
| Открыть дело | 1 | 1 |
| Ответить | 1 | 2 (прочитать попытку → записать ответ и прогресс) |

Между делами состояние не перезагружается: клиент обновляет его по ответу сервера. Нажатие на вариант сразу подсвечивается, не дожидаясь ответа сервера. Модули фронтенда грузятся параллельно (`modulepreload`), конфигурация отдаётся без базы и кэшируется. Бюджет запросов проверяет тест `tests/perf.test.js`.

## Честность

- Правильные ответы не покидают сервер: браузер получает вопрос с перемешанными вариантами `a–d`, а сервер знает, какой из них верный.
- Время считает сервер — от `open` до `answer`. Если игрок ушёл со страницы, просроченное дело засчитывается как тайм-аут при следующем запросе.
- Ответ записывается атомарно: `UPDATE … WHERE position = ?`. Двойной клик или вторая вкладка не дадут ответить дважды.
- Лимит попыток проверяется одним `INSERT … SELECT … WHERE count < allowed`, без гонок.
- Незаконченная смена продолжается, даже если игрок зашёл с другого устройства.
- Ограничение: игрок определяется по фамилии, имени и группе. Под другим именем можно сыграть ещё раз, но такие записи видны в кабинете, и их можно удалить.

## Как добавить дела

Отредактируйте `server/data/cases.js`. Правильный вариант всегда первый, у нового дела должен быть новый `id`, а `topic` — одна из тем. Главы берут дела по темам (`server/game/rules.js → CHAPTERS`).
